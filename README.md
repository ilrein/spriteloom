# spriteloom

Live at **https://spriteloom.app** (the D1 database keeps its original
name internally — D1 cannot be renamed).

A low-color sprite foundry: pixel art as **deterministic JSON recipes**, not
images. Think meshy-for-pixel-art, except there is no image model anywhere — a
tiny constrained DSL (rect, ellipse, line, mirror, dither, scatter, replace, …)
is rasterized by the same engine in the browser (live editor) and in a
Cloudflare Worker (API). Style target: lightweight retro — from 1-bit
(Urizen/Kenney) up to 16-color (PICO-8 territory).

## Why recipes

- **Deterministic** — same recipe, same pixels, forever. `scatter` is seeded.
- **Constrained by construction** — 2–16 indexed colors, on-grid, 8–64px. No
  anti-aliasing smear, no off-grid "AI pixel art" artifacts.
- **Editable & parametric** — recolor via `palette.colors` or the `replace` op,
  rescale, or tweak a sprite by editing JSON, not repainting. The recipe is the
  artifact.
- **Agent-native** — agents iterate via ASCII output (`?format=text`) and read
  the DSL from `/api/spec`. See `.claude/skills/spriteloom/SKILL.md` (autoloads in
  Claude Code sessions inside this repo).

## Stack

Cloudflare Worker + static assets, Vite 8 + `@cloudflare/vite-plugin`. The
engine has zero runtime dependencies; the PNG encoder writes indexed PNGs by
hand (bit depth 1/2/4 chosen from palette size, CompressionStream for the zlib
stream) — sprite files are ~100–300 bytes. The dashboard UI is React 19 +
Tailwind 4 + shadcn/ui (sidebar, header navbar with search, cards/table,
avatar dropdown) themed pixel-style: mono type, zero radius, 2px borders.
User avatars are deterministic 8×8 identicons generated by the engine itself
from the username hash.

## Develop

```bash
bun install
bun run dev        # vite + worker, one server
bun test           # engine + png tests
bun run sprites    # print example sprites as ASCII in the terminal
bun run deploy     # vite build && wrangler deploy
```

## API

| Route | What |
|---|---|
| `POST /api/render` | recipe JSON → PNG (`?scale=N`), ASCII (`?format=text`), or rows (`?format=json`) |
| `GET /api/spec` | machine-readable DSL spec |
| `GET /api/examples` | example recipes |
| `GET /api/examples/:name.png` | rendered example |
| `/api/auth/*` | better-auth (email/password + username; cookie sessions) |
| `GET /api/sprites?sort=new\|top&page=N&q=text&tag=t&user=name` | community feed with search + tag filter (`liked` flags when signed in) |
| `POST /api/sprites` | publish `{name, recipe, tags?, parentId?}` (auth; ≤5 lowercase tags; parentId = remix lineage) |
| `GET /api/tags` | top 30 tags with counts |
| `GET /api/sprites/:id` / `:id.png` | one sprite as JSON or rendered PNG (shareable, cached) |
| `POST /api/sprites/:id/like` | toggle like (auth) |
| `DELETE /api/sprites/:id` | delete own sprite (auth) |

Invalid recipes → `400 {"errors": ["ops[2]: ..."]}`.

## Social layer

Accounts are better-auth on D1 (via kysely-d1): username + email/password,
cookie sessions, no email verification in v1. Sprites live in D1 as recipe
JSON (≤8KB) — the feed re-renders every sprite client-side from its recipe,
and `/api/sprites/:id.png` renders shareable PNGs on demand, so there are no
image blobs anywhere. Remixes carry `parentId` lineage. Local dev: put a
`BETTER_AUTH_SECRET` in `.dev.vars`, run
`bunx wrangler d1 migrations apply bitloom --local`, then `bun run dev`.

## DSL at a glance

```json
{
  "size": 16,
  "palette": { "colors": ["#151515", "#7ac74f", "#3e7a2e"], "transparent": true },
  "ops": [
    { "op": "ellipse", "cx": 7, "cy": 10, "rx": 6, "ry": 4 },
    { "op": "ellipse", "cx": 7, "cy": 7, "rx": 4, "ry": 3 },
    { "op": "mirror", "axis": "x" },
    { "op": "dither", "x": 3, "y": 12, "w": 10, "h": 2, "pattern": "checker", "v": 2 },
    { "op": "px", "at": [[5, 8], [5, 9], [10, 8], [10, 9]], "v": 2 }
  ]
}
```

Most of the slime in the gallery. Every pixel is a palette index (0 = bg,
written by each op's `v`); ASCII output maps indices to `.#23456789abcdef`.
Constraints: size 8–64, ≤256 ops, 2–16 colors. Legacy 1-bit palettes
(`{"fg": ..., "bg": ...}`) still work.
